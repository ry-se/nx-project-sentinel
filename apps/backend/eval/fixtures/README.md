# Eval fixtures

Each fixture is a `.json` file next to the image it labels, in this directory (or a
subdirectory — `run_eval.py` walks recursively). Schema:

```json
{
  "image": "my_capture.png",
  "pose": { "alt_m": 300, "fov_deg": 60 },
  "ground_truth": [{ "cls": "armored_fighting_vehicle", "rear": [400, 260], "front": [400, 240] }]
}
```

- `image` — filename relative to the fixture's own directory.
- `pose` — optional. When present, `run_eval.py` converts pixel localization error to an
  **estimated** ground-distance error (metres) for that image, using a nadir
  (straight-down) ground-sample-distance assumption: `alt_m` (capture altitude) and
  `fov_deg` (vertical field of view). This is a simplification for benchmarking — it does
  NOT account for oblique/grazing capture angles the way the frontend's
  `estimateGeoUncertaintyM` does (that needs a real raycast against terrain, which this
  harness doesn't have). Omit `pose` and the report skips the geo-error column for that
  image, reporting pixel error only.
- `ground_truth` — one entry per real target in the image. `cls` MUST be one of the
  three `DetectionClass` values (checked against the same enum the schema-parity test
  guards). `rear`/`front` are pixel keypoints, same convention as `ImageAnnotation` in the
  frontend (rear→front sets facing).

## `smoke_test/`

The fixtures in `smoke_test/` are **not real accuracy benchmarks** — they're tiny
synthetic images (a colored rectangle on a flat background, generated by
`smoke_test/generate.py`) that exist only to prove `run_eval.py` runs end-to-end against
the deterministic `stub` detector provider without needing a real model or network
access. Real accuracy numbers require real labeled photos — add them as sibling fixture
files (not inside `smoke_test/`) when available.
